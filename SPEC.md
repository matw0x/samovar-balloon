## 1. Назначение

«Пыхтун» — летательный аппарат, гондолой которого служит пузатый латунный самовар. Угли в топке нагревают воздух, через трубу он уходит в матерчатую оболочку над самоваром и создаёт подъёмную силу. Аппарат перевозит одного пилота над пересечённой местностью, умеет медленно ковылять по земле на самоварных ножках и, в отличие от любого другого транспорта, заваривает чай тем же паром, на котором летит. Плавать не умеет: вода гасит топку.

![Самоварный аэростат «Пыхтун»](docs/pyhtun.svg)

---

## 2. Стихия и конструкционный элемент

**Стихия:** воздух.

**Конструкционный элемент:** не менее одного элемента, обеспечивающего подъёмную силу.

**Как реализован элемент:**

> Тепловая оболочка (аэростат) объёмом `balloon_volume_m3`. Её грузоподъёмность `lift_capacity_kg = balloon_volume_m3 × 0.25`. Полёт возможен, только если оболочка цела (`balloon_intact == True`) и масса аппарата не превышает грузоподъёмности. Порванная оболочка означает аварийную посадку и запрет полёта до починки.

**Ограничения стихии:**

- Основной режим — полёт.
- По земле передвигается медленно и с повышенным расходом пара (на ножках, оболочка сложена).
- В воду не входит ни в каком виде.

## 3. Публичный интерфейс

Разработчик реализует ровно то, что описано в этом разделе. Всё остальное — внутренняя реализация.

### 3.0. Общие правила (действуют для всех методов)

1. **Число** — значение типа `int` или `float`, но **не** `bool`. Нечисловое значение там, где ожидается число, → `TypeError`.
   Число должно быть конечным: `nan`, `inf`, `-inf` → `ValueError` (это проверка значения, она идёт после проверки типа).
2. Строковый параметр, переданный не как `str`, → `TypeError`.
3. Порядок проверок: сначала типы (`TypeError`), затем значения (`ValueError`), затем доменные правила (раздел 6.3).
4. **Атомарность:** метод, выбросивший исключение, не меняет состояние объекта.
5. Числовые атрибуты хранятся как `float` (переданный `int` приводится к `float`).
6. Дробные результаты тесты сравнивают с точностью до 6 знаков после запятой.
7. Достаточность пара проверяется **точным** сравнением `float` без допуска, остаток пара не округляется. Пример: при `steam = 0.6` после двух `move(0.1, "air")` остаётся `0.19999999999999996`, и третий `move(0.1, "air")` (нужно `0.2`) выбрасывает `SamovarOutOfSteam`.

### 3.2. Конструктор

```python
def __init__(
    self,
    name: str,
    mass_kg: float,
    balloon_volume_m3: float,
    max_speed_kmh: float,
    steam: float = 100.0,
) -> None:
```

| Параметр | Тип | Единица | Допустимый диапазон | По умолчанию |
|---|---|---|---|---|
| name | str | — | строка, содержащая хотя бы один непробельный символ | — |
| mass_kg | число | кг | > 0 | — |
| balloon_volume_m3 | число | м³ | > 0 | — |
| max_speed_kmh | число | км/ч | > 0 | — |
| steam | число | ед. пара | 0 … 100 включительно | 100.0 |

**Исключения конструктора:**

- `TypeError` — `name` не `str`; любой числовой параметр не число (в том числе `bool`, `None`, `str`).
- `ValueError` — `name` пустой или состоит только из пробельных символов.
- `ValueError` — `mass_kg`, `balloon_volume_m3` или `max_speed_kmh` ≤ 0.
- `ValueError` — `steam` < 0 или `steam` > 100.
- `ValueError` — любой числовой параметр равен `nan`, `inf` или `-inf`.

**Начальное состояние:** `position_km == 0.0`, `is_flying == False` (аппарат стоит на земле), `balloon_intact == True`.

### 3.3. Атрибуты

Все атрибуты **только для чтения**: попытка присвоить значение → `AttributeError`.

| Атрибут | Тип | Единица | Доступ | Описание |
|---|---|---|---|---|
| name | str | — | чтение | Имя аппарата |
| mass_kg | float | кг | чтение | Полная масса (аппарат + пилот) |
| balloon_volume_m3 | float | м³ | чтение | Объём оболочки |
| max_speed_kmh | float | км/ч | чтение | Максимальная скорость в воздухе |
| steam | float | ед. пара | чтение | Текущий запас пара, 0 … 100 |
| position_km | float | км | чтение | Суммарное пройденное расстояние |
| is_flying | bool | — | чтение | Находится ли аппарат в воздухе |
| balloon_intact | bool | — | чтение | Цела ли оболочка |
| lift_capacity_kg | float | кг | чтение | Грузоподъёмность: `balloon_volume_m3 × 0.25` |
| can_fly | bool | — | чтение | `True` ⇔ `balloon_intact` и `mass_kg ≤ lift_capacity_kg` и `steam > 0`. Означает допустимость полёта по состоянию, но не гарантирует, что пара хватит на конкретную дистанцию: это проверяет `move` (`SamovarOutOfSteam`) |

### 3.4. Методы

#### 3.4.1. move

```python
def move(self, distance_km: float, terrain: str) -> float:
```

**Назначение:** перемещает аппарат на заданное расстояние в заданной среде.

**Параметры:**

- `distance_km` — число, км, > 0.
- `terrain` — среда: `"air"`, `"ground"`, `"water"`.

**Возвращает:** время перемещения в часах (`float`).

**Изменяет:** `position_km` (+ `distance_km`), `steam` (− расход), `is_flying`.

**Правила:**

| terrain | Скорость | Расход пара | is_flying после | Дополнительные условия |
|---|---|---|---|---|
| "air" | max_speed_kmh | distance_km × 2 | True | оболочка цела; mass_kg ≤ lift_capacity_kg |
| "ground" | max_speed_kmh × 0.25 | distance_km × 3 | False | — |
| "water" | — | — | — | всегда `SamovarCannotSwim` |

- Расход, в точности равный запасу, допустим: после перемещения `steam == 0`.
- Взлёт с земли и посадка отдельно не моделируются: `move(..., "air")` с земли означает взлёт, `move(..., "ground")` из воздуха — посадку.

**Исключения** (в порядке проверки):

1. `TypeError` — `distance_km` не число или `terrain` не `str`.
2. `ValueError` — `distance_km` ≤ 0.
3. `ValueError` — `terrain` не из списка.
4. `SamovarCannotSwim` — `terrain == "water"`.
5. `SamovarBalloonTorn` — `terrain == "air"` и оболочка порвана.
6. `SamovarTooHeavy` — `terrain == "air"` и `mass_kg > lift_capacity_kg`.
7. `SamovarOutOfSteam` — расход больше текущего `steam`.

#### 3.4.2. can_overcome

```python
def can_overcome(self, obstacle: str) -> bool:
```

**Назначение:** проверяет, может ли аппарат в текущем состоянии преодолеть препятствие. Состояние **не меняется**, пар **не тратится**.

**Параметры:** `obstacle` — `"wall"`, `"river"`, `"low_bridge"`.

**Возвращает:** `True` / `False`.

**Правила:**

| obstacle | Результат True, если |
|---|---|
| "wall" (стена) | `is_flying` |
| "river" (река) | `can_fly` (вплавь нельзя, только по воздуху) |
| "low_bridge" (низкий мост) | `not is_flying` (под мостом можно только пешком) |

**Почему правила разные:** `wall` и `low_bridge` зависят от текущего положения (`is_flying`), а `river` — от способности лететь (`can_fly`): стену перелетают тем, что уже в воздухе, а реку пересекают полётом, который ещё нужно совершить. Поэтому результаты расходятся:

- на земле при `can_fly == True`: `wall` → False, `river` → True;
- в воздухе при `steam == 0`: `wall` → True, `river` → False.

**Исключения:**

- `TypeError` — `obstacle` не `str`.
- `ValueError` — `obstacle` не из списка.

#### 3.4.3. calculate_steam

```python
def calculate_steam(self, distance_km: float, terrain: str) -> float:
```

**Назначение:** рассчитывает расход пара на перемещение без изменения состояния.

**Параметры:** те же, что у `move`.

**Возвращает:** расход пара (`float`) по формуле из 3.4.1.

**Исключения:** `TypeError`, `ValueError`, `SamovarCannotSwim` — как у `move`. **Не** выбрасывает `SamovarBalloonTorn`, `SamovarTooHeavy`, `SamovarOutOfSteam`: метод считает стоимость, а не проверяет возможность.

#### 3.4.4. add_coal

```python
def add_coal(self, amount: float) -> None:
```

**Назначение:** подкинуть угля, то есть пополнить запас пара.

**Параметры:** `amount` — число, > 0.

**Возвращает:** `None`.

**Изменяет:** `steam = min(100.0, steam + amount)` (результат всегда `float`).

**Исключения:**

- `TypeError` — `amount` не число.
- `ValueError` — `amount` ≤ 0.

#### 3.4.5. brew_tea

```python
def brew_tea(self, cups: int) -> None:
```

**Назначение:** заварить чай паром из котла. Доступно в любом состоянии (в воздухе, на земле, с порванной оболочкой).

**Параметры:** `cups` — количество чашек, `int` (не `bool`), ≥ 1.

**Возвращает:** `None`.

**Изменяет:** `steam` (− `cups × 5`). Позиция и `is_flying` не меняются.

**Исключения:**

- `TypeError` — `cups` не `int` (в том числе `float`, `bool`, `str`).
- `ValueError` — `cups` < 1.
- `SamovarOutOfSteam` — `cups × 5` > `steam`.

#### 3.4.6. tear_balloon

```python
def tear_balloon(self) -> None:
```

**Назначение:** доменное событие «оболочка порвана» (птица, сук, молния).

**Изменяет:** `balloon_intact = False`; `is_flying = False` (аварийная посадка). `position_km` и `steam` не меняются.

**Исключения:** нет. Повторный вызов ничего не меняет.

#### 3.4.7. patch_balloon

```python
def patch_balloon(self) -> None:
```

**Назначение:** залатать оболочку.

**Изменяет:** `balloon_intact = True`. Остальное состояние, включая `is_flying`, не меняется. После `tear_balloon` аппарат уже на земле и после починки остаётся на земле; если оболочка цела и аппарат в воздухе, он остаётся в воздухе.

**Исключения:** нет. Вызов при целой оболочке ничего не меняет.

#### 3.4.8. get_status

```python
def get_status(self) -> dict:
```

**Назначение:** возвращает снимок состояния.

**Возвращает:** **новый** словарь ровно с ключами:

| Ключ | Тип |
|---|---|
| "name" | str |
| "steam" | float |
| "position_km" | float |
| "is_flying" | bool |
| "balloon_intact" | bool |
| "can_fly" | bool |

Изменение возвращённого словаря не влияет на объект.

### 3.5. Сводка констант домена

| Величина | Значение |
|---|---|
| Подъёмная сила оболочки | 0.25 кг на 1 м³ |

| Скорость по земле | max_speed_kmh × 0.25 |

| Расход пара по земле | 3 ед. на 1 км |

| Максимальный запас пара | 100 ед. |

## 4. Сценарии

Если не сказано иное, используется эталонный аппарат: `SamovarBalloon("Пыхтун", mass_kg=150, balloon_volume_m3=800, max_speed_kmh=40)` — грузоподъёмность 200 кг, пар 100.

### 4.1. Модульные тесты (AAA)

**Сценарий 1. Обычный полёт**
Дано: эталонный аппарат, `steam = 100`.
Когда: `move(20, "air")`.
Тогда: возвращается `0.5`; `position_km == 20`; `steam == 60`; `is_flying == True`.

**Сценарий 2. Полёт с нехваткой пара**
Дано: `steam = 10`.
Когда: `move(30, "air")`.
Тогда: `SamovarOutOfSteam` с `required == 60`, `available == 10`; состояние не изменилось.

**Сценарий 3. Перегруз**
Дано: `mass_kg = 250`, `balloon_volume_m3 = 800` (грузоподъёмность 200).
Когда: `move(1, "air")`.
Тогда: `SamovarTooHeavy`; `can_fly == False`.

**Сценарий 4. Заправка углём**
Дано: `steam = 20`.
Когда: `add_coal(50)`.
Тогда: `steam == 70`.

| Случай | Ожидание | TC |

## 6. Исключения

### 6.1. Иерархия

```
Exception
└── CrazyVehicleError
    └── SamovarError
        ├── SamovarCannotSwim
        ├── SamovarOutOfSteam
        ├── SamovarTooHeavy
        └── SamovarBalloonTorn
```

Ошибки параметров — стандартные исключения (`TypeError`, `ValueError`). Нарушения правил домена — доменные исключения. `RuntimeError` не используется.

`SamovarOutOfSteam` создаётся как `SamovarOutOfSteam(required: float, available: float)` (аргументы можно передавать и по имени) и имеет публичные атрибуты `required: float` (сколько пара нужно) и `available: float` (сколько есть). Остальные доменные исключения создаются со строкой-сообщением.

### 6.2. Таблица

| Ситуация | Исключение | Сообщение |
|---|---|---|
| Параметр неверного типа | TypeError | "<param> must be a number" / "<param> must be a string" / "cups must be an int" |
| Пустое имя | ValueError | "name must not be empty" |
| Неположительные масса / объём / скорость | ValueError | "<param> must be positive" |
| Пар вне 0…100 при создании | ValueError | "steam must be between 0 and 100" |
| Неположительная дистанция | ValueError | "distance_km must be positive" |
| Неизвестная среда / препятствие | ValueError | "unknown terrain: <x>" / "unknown obstacle: <x>" |
| Неположительный уголь | ValueError | "amount must be positive" |
| Меньше одной чашки | ValueError | "cups must be at least 1" |
| Попытка войти в воду | SamovarCannotSwim | "samovar cannot swim: water puts out the fire" |
| Не хватает пара | SamovarOutOfSteam | "not enough steam: required X, have Y" |
| Масса больше грузоподъёмности | SamovarTooHeavy | "too heavy to fly: mass X kg, lift Y kg" |
| Полёт с порванной оболочкой | SamovarBalloonTorn | "balloon is torn" |

Тесты проверяют тип исключения и атрибуты `required` / `available`. Текст сообщения тестами не проверяется.

### 6.3. Порядок проверок

`TypeError` → `ValueError` → `SamovarCannotSwim` → `SamovarBalloonTorn` → `SamovarTooHeavy` → `SamovarOutOfSteam`. При нескольких нарушениях выбрасывается первое по этому порядку.

## 7. Что вне рамок

- Высота полёта, ветер, погода и температура не моделируются.
- Взлёт и посадка не являются отдельными действиями (см. 3.4.1).
- Груз и изменение массы после создания не поддерживаются.
- Аппарат не взаимодействует с другими транспортами.
- Количество воды в самоваре и сорта чая не моделируются.
- Нет графики и визуализации в коде (картинка в ТЗ только иллюстрирует).
- Нет сохранения состояния между запусками, работы с файлами, сетью и API.
